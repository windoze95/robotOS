# robotOS 0.4.0

This release makes robotOS a Hermes remote with saved chats, recoverable tasks and an interface
sized for the R1. It is a minor release because it changes the backend and settings contract and
adds substantial capabilities beyond v0.3.6. The release tag produces version name `0.4.0` and
Android version code **4000**.

## Changes since v0.3.6

- **Hermes is the only agent backend.** Push-to-talk sends the transcribed request to Hermes.
  OpenAI is used only for transcription and speech. The ChatGPT/Custom backend choices, live
  speech-to-speech mode, on-device SMS assistant and separate bridge relay are removed. Hermes
  can use the R1's permissioned device API; configured owner SMS passthrough remains available.
- **Chats survive restart.** Each conversation retains its transcript, draft, reading position
  and Hermes session. Incoming replies preserve your place while reading older text.
- **Tasks can be recovered.** Compatible Hermes hosts expose Runs progress, model choices,
  explicit cancellation and touch-only Allow once/Deny approvals. Saved task identities help
  recover interrupted requests without submitting them again. Unsupported hosts retain legacy
  chat. Unknown remote outcomes remain explicit.
- **Controls fit the R1.** Larger text and touch targets, black/white/orange styling, native dark
  dialogs and keyboard styling, focused settings and Quick controls improve readability and
  access to brightness, speech volume, Quiet mode and Stay reachable. The wheel scrolls while
  reading and changes volume during playback.
- **Voice input can be edited or cancelled before submission.** Tap the orange listening screen
  to keep the words as an editable draft, or swipe to discard the turn. These gestures stop
  being available after the request has been handed to Hermes.
- **Device tools have separate permissions and receipts.** `speak`, `show`, `set_volume` and
  `save_recipient` start disabled. Mutations retain receipts; an uncertain outcome does not
  authorize a retry. Hermes SMS sends and owner passthrough share the daily allowance.
- **The agent can have a name.** Set it on the R1 under Hermes → Name. The new `set_name` host
  tool can set an empty name once; changing an existing name stays under the user's control.

## Before upgrading

- This is an app-only update for `dev.r1ptt`, with the existing stable signer and minimum
  Android 13/API 33. It does not install an OS, firmware, Magisk module or Hermes host component.
  Do not uninstall or force a downgrade to update.
- **The old provider settings are not migrated.** The current format uses `agent` for the Hermes
  connection and `openaiKey` for speech. Devices still using `providers`/`activeProvider` must
  configure Hermes and speech in the current settings format after upgrading. The project's
  development R1 had already saved the new format. Keeping app data does not make the retired
  backend configuration compatible.
- Code 4000 is newer than the published v0.3.6/code 3006 and the inspected same-signer
  `0.3.6-daily-driver-dev` and `0.3.6-luminous-dev` APKs, both code 3006. A separately built APK
  at code 4000 or higher needs its own compatibility check; the current device version could
  not be read because no R1 was attached during release preparation.
- Runs, approvals and model selection depend on host capabilities. `set_name` requires the
  updated `robotos` MCP module (1.2.0) and skill on the Hermes host. PR #32 explicitly recorded
  that deployment as pending; publishing this APK does not deploy it. Manual naming on the R1
  is available independently.

## Validation and remaining acceptance

Release validation runs Android unit/Robolectric tests, debug/release builds, lint, Python
MCP/setup tests and Node acceptance/release tests. The signed pipeline checks main ancestry,
increasing version codes, APK identity, the stable certificate and signed update metadata.

Earlier same-signer development builds were installed on an R1 with chats preserved, and the
repository records UI checks and a live Hermes Runs round trip. Those observations are not a
hardware acceptance pass for this tagged APK. No device installation is part of this release.

[Hardware acceptance issue #16](https://github.com/windoze95/robotOS/issues/16) remains open.
Physical wheel/button behavior, tap/swipe while holding the button, voice/audio interruption,
approval review, carrier delivery reports, sleep/reconnect and reboot recovery, cable power
transitions, updater installation/recovery and matched overnight standby measurements remain
pending. The dark theme is not evidence of lower battery use. See
[daily-use evidence](https://github.com/windoze95/robotOS/blob/v0.4.0/docs/DAILY_DRIVER.md),
[acceptance](https://github.com/windoze95/robotOS/blob/v0.4.0/docs/ACCEPTANCE.md) and
[app-update acceptance](https://github.com/windoze95/robotOS/blob/v0.4.0/docs/UPDATES.md).
