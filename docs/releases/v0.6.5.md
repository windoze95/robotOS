The R1 now downloads only what changed on your host, instead of the whole workspace every 30
seconds. The hub stops logging every check-in as a change.

**R1**
- Each sync still checks in, so commands and recovery behave as before. It then reads the host's
  change feed and fetches only the lists it names: notes, prompts, replies or the shared resume
  point (#51). Everything is fetched on the first sync after a start, when the host says the R1
  missed pruned history, or from a hub without the feed. A failed download is retried on the
  next pass.
- The workspace file and the encrypted device identity are no longer rewritten when nothing
  changed. Each check-in used to rewrite the identity twice.
- Screens read saved data without waiting for a write to finish, so a sync can no longer stall the
  interface while the disk catches up.

**Hub**
- A check-in adds a change only when the R1 reports something new, such as battery, charging, app
  version, settings or policy state. Device liveness still updates in the console (#52).
- Change history older than seven days is pruned.
- `GET /changes?after=latest` returns the newest position. Pages report `more` when another page
  follows. A client that missed pruned history, or whose position is ahead of a replaced database,
  is told to reload.
- The console starts at the newest change instead of replaying the whole history every time it
  opens. It reloads its list if it is told to.

Update both. The new app works with an older hub by downloading everything as before, and the
updated hub works with older apps. Update a native hub with `tools/hub-setup.sh --hub-only` on its
host, or a container install with `docker compose pull && docker compose up -d --no-build`. No
database migration is needed.

Automated tests cover the following:
- syncs that fetch only the changed lists;
- a reload after missed history;
- a failed download retried on the next pass;
- a hub without a change feed;
- writes skipped when nothing changed;
- readers not waiting for a slow disk;
- check-ins that change nothing adding no change rows;
- the feed's head, paging and reset;
- the console starting at the newest change and reloading on reset.

On a physical R1 with a signed 0.6.5 preflight, connected to the updated hub and idle on its
charger with the screen off, two minutes of syncing used about 3 KB of data received instead of
about 200 KB (4.3 KB sent instead of 9.3 KB). The hub added no change rows for its check-ins,
where it had added four.
